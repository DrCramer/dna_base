# Лабораторный реестр ДНК

Веб-сервис для лабораторного ДНК-реестра. Проект содержит FastAPI backend, PostgreSQL, Alembic, React/Vite frontend и Docker Compose. Внешний порт сервиса: `4001`.

Текущая модель данных: `партии -> объекты -> рабочие сессии -> повторяемые stage_events -> исполнители -> аудит`. Excel остается форматом импорта/экспорта, а PostgreSQL является основным источником данных.

История изменений и апгрейдов ведется в [`CHANGELOG.md`](CHANGELOG.md).

## Запуск через Docker

```bash
docker compose up -d --build
```

Открыть интерфейс: `http://localhost:4001`

Если нужно быстро сменить внешний порт, задайте `APP_PORT` в `.env`:

```bash
APP_PORT=4010
```

Или разово передайте переменную в команду:

```bash
APP_PORT=4010 docker compose up -d --build
```

Тестовые логины в dev-сборке:

- `admin / admin123`
- `user / user123`
- `viewer / viewer123`

## Локальный запуск

Backend:

```bash
cd backend
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL=postgresql+asyncpg://dna:dna@localhost:5432/dna_registry
alembic -c ../alembic.ini upgrade head
uvicorn app.main:app --reload --port 8000
```

Frontend:

```bash
cd frontend
npm install
npm run dev
```

Vite будет доступен на `http://localhost:5173` и проксирует `/api` в backend.

## Первый admin

В dev-режиме пользователи создаются автоматически при старте приложения. Для production можно создать или обновить admin:

```bash
docker compose exec backend python -m app.commands.create_admin admin 'new-password'
```

## Импорт реестра

1. Войти под `admin` или `user`.
2. Открыть `Импорт реестра`.
3. Загрузить `.xlsx` файл.
4. Проверить preview: партия, новые/существующие объекты, найденные этапы, пропущенные строки, дубликаты.
5. Нажать `Импортировать`.

Импортер:

- ищет лист `список объектов`;
- извлекает номер партии из имени файла: `143 партия.xlsx`, `партия 143.xlsx`, `№ 148 реестр.xlsx`;
- создает или находит запись в `parties`, сохраняет контрольные строки партии;
- читает русские заголовки, а не буквенные координаты;
- не доверяет `usedRange`/`dimension`;
- игнорирует служебные строки и одиночные мусорные значения далеко внизу листа;
- сохраняет исходные значения каждой строки в `raw_registry_json`;
- не создаёт дубль объекта, если объект уже есть по `№ рег РЦСМЭ` или `№ постановления`;
- для существующих объектов обновляет регистрационные поля и Excel-этапы без дублирования объекта;
- пишет этапы в canonical `stage_events`, legacy-таблицы пока сохраняются для совместимости.

Для приложенного `№ 148 реестр.xlsx` ожидается `100` объектов, строки `2-101`.
Для приложенного `№ 132 реестр.xlsx` ожидается `99` объектов и заполненные лабораторные этапы.

## Лабораторные этапы из Excel

При импорте реестра сервис переносит связанные этапы из колонок листа `список объектов`.
События создаются только если в соответствующем блоке есть данные; пустые блоки не создают пустые записи.
Исходные значения каждого блока сохраняются в `raw_json` события.

Поддерживаемые блоки:

- `18-27` - пробоподготовка: фотофиксация, отмывка, размельчение/изъятие тканей, мельница;
- `28-35` - первое выделение ДНК и измерение концентрации;
- `36-44` - повторное выделение ДНК и измерение концентрации;
- `45-49` - PCR;
- `50-55` - форез;
- `56-65` - анализ фореза, до 5 попыток парами `дата + исполнитель`.

Повторный импорт того же реестра не удваивает Excel-события: записи с `raw_json.source = registry_excel` для тех же блоков заменяются актуальными данными. Будущие ручные события не должны затрагиваться этим механизмом.

## Партии и рабочие сессии

Раздел `Партии` показывает список партий, контрольные поля, прогресс этапов и объекты партии. Клик по номеру партии открывает обычную таблицу объектов с фильтром по этой партии.

Раздел `Этапы работ` позволяет массово заполнить этап для объектов выбранных партий:

- сначала выполняется preview: сколько объектов будет затронуто и какой будет номер повтора;
- commit создает `work_session`, связывает объекты через `work_session_objects` и добавляет новые `stage_events`;
- отмена сессии помечает ее события как `is_cancelled`, история не удаляется физически.

Excel-импорт имеет источник `registry_excel`, ручные массовые сессии - `manual`, RT-импорт остается отдельным источником данных.

## Карточка объекта

Карточка объекта открывается из таблицы объектов. Вкладки:

- `Обзор` - timeline canonical-этапов;
- `Регистрация` - основные поля объекта и партия;
- `Пробоподготовка` - этапы пробоподготовки;
- `Измельчение` - мельница/стаканы;
- `ДНК` - выделения ДНК;
- `RealTime` - концентрации из реестра и результаты RT/qPCR-импорта;
- `ПЦР` - постановка PCR;
- `Электрофорез` - форез;
- `Анализ` - попытки анализа фореза;
- `Файлы`, `История` - зарезервированы для следующих итераций.

Роль `viewer` просматривает данные без действий импорта и редактирования.

## Поиск и справочники

Раздел `Поиск` ищет по регистрационным полям объекта, партиям, тексту объекта, этапам, исполнителям, методам, raw/detail-данным этапов и RT-результатам.

Раздел `Справочники` содержит сотрудников. Исполнители, найденные в Excel или массовых сессиях как raw-текст, создаются как неподтвержденные; их можно подтвердить в справочнике.

## Отчёты

Раздел `Отчёты` предназначен для руководителя лаборатории. В нём доступны:

- `Обзор` с KPI по активным партиям, объектам, незавершённым этапам и проблемным признакам;
- `Контроль партии` с отдельной таблицей контрольных полей, статусами `Нет данных`, `Без проблем`, `Есть замечания`, `Критично` и Excel-экспортом;
- `Ход работы` с процентами готовности по этапам и отстающим этапом;
- `Статистика` по неделям, месяцам и годам.

Фильтры отчётов учитывают год `case_year`, партии, период, этап, исполнителя, тип объекта, коробку, архивные и пустые партии. Выбранные фильтры сохраняются в URL.

## Импорт RT/qPCR

Экран `Импорт RT` принимает `.xls`, `.xlsx`, `.csv`. MVP поддерживает универсальную таблицу и определяет ABI/QuantStudio по признакам `Sample Name`, `Target Name`, `Ct`, `Quantity`, `Degradation Index`. Сопоставление с объектами идет по `№ рег РЦСМЭ`, `№ постановления` и числовой основе.

## Экспорт

Экран `Экспорт` создает `.xlsx` с листами:

- `список объектов` с 65 колонками исходного формата;
- `Данные для вып.окна` со справочниками;
- `Пустой` с базовой структурой.

Экспорт работает при пустых полях, сохраняет исходные raw-значения там, где они доступны, и подставляет последние актуальные значения canonical-этапов в старые 65 колонок.

## Backup

База:

```bash
docker compose exec postgres pg_dump -U dna -d dna_registry > backup.sql
```

Файлы:

```bash
docker run --rm -v dna_base_storage:/data -v "$PWD":/backup alpine tar czf /backup/storage-backup.tgz -C /data .
```

Восстановление базы:

```bash
docker compose exec -T postgres psql -U dna -d dna_registry < backup.sql
```

## Структура

- `backend/app/models` - SQLAlchemy модели.
- `backend/app/parsers` - импорт реестров и RT/qPCR.
- `backend/app/services` - бизнес-логика импорта, экспорта, аудита.
- `backend/app/api` - FastAPI маршруты.
- `frontend/src` - React UI.
- `alembic/versions` - миграции БД.
